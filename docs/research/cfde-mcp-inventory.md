# CFDE / Common Fund MCP server inventory

Researched 2026-10-14. Purpose: list the MCP (Model Context Protocol) servers that already exist for CFDE and Common Fund programs/DCCs, so we know what a consolidated usage-metrics effort would be measuring.

Method: `gh search repos` and `gh search code` (org-scoped, for example `streamableHttp org:MaayanLab` and `FastMCP org:broadinstitute`), the official MCP Registry API (`registry.modelcontextprotocol.io/v0/servers?search=…`), npm search and download APIs, PyPI JSON lookups by name, Glama and BioContextAI listings, and web search. Every "live" claim below was checked with an MCP `initialize` POST on 2026-10-14.

## Implications for metrics

1. **Official CFDE MCP footprint is small and almost entirely remote.** There are 4 live official or CFDE-affiliated servers: cfde-mcp, GlyGen, PWB and PerturbSeqr. All 4 are **remote Streamable HTTP**, so they can be measured centrally at the server. Only 1 official server is **local stdio** (Bridge2AI Standards Explorer), and its usage is visible only through PyPI downloads and Synapse API logs. 1 more (DDKG) is in design.
2. **Dominant stack: the official TypeScript SDK with stateless Streamable HTTP (the Ma'ayan Lab pattern).** Three of the four live servers come from one lab and share one scaffold (`MaayanLab/mcp-template`, then cfde-mcp, then PerturbSeqr). One shared Express or Next.js middleware, or an SDK request hook, that emits `{server, tool, client_name/version from initialize, api_key_id, latency, status}` would instrument most of the official footprint at once. GlyGen and Bridge2AI use Python FastMCP and would need the FastMCP-middleware equivalent.
3. **Stateless mode means no MCP session ID** (`sessionIdGenerator: undefined`, `stateless_http=True`). Session-level metrics (sessions, calls per session) cannot come from the protocol. Count `tools/call` per request and take client identity from `initialize.clientInfo`, or from the cfde-mcp API key.
4. **No server has telemetry today** beyond stdout logs and ingress/access logs. Ingress logs (k8s nginx for the maayanlab.cloud / cfde.cloud hosts, uvicorn for GlyGen) are the zero-code starting point, but every request is `POST /mcp`, so the tool name is hidden in the JSON body. Body-level logging is needed to get per-tool counts.
5. **Remote connectors hide the end user.** GlyGen tells users to add it as a claude.ai custom connector, so requests arrive from Anthropic egress. Measure clients by `clientInfo` rather than IP.
6. **Most DCC data access over MCP happens through third parties** (GTEx ×4, Enrichr ×2, Pharos, CELLxGENE, plus aggregators). The DCCs cannot measure that traffic at the MCP layer. It appears only as API traffic, and possibly by User-Agent. Package download counts (npm `@pipeworx/mcp-gtex` 431/mo, `enrichr-mcp-server` 125/mo) are the only public proxy.
